    Partie 1 - En classe - environ 1 h

    Les bases

    Niveau 0 - 5 min

    Ce qu'est vraiment un site web

    Un site web est un dossier de fichiers. Votre navigateur ouvre un fichier, le lit de haut en bas, et dessine ce qu'il décrit. C'est tout.

    Si vous avez déjà utilisé un moteur de jeu, l'idée vous sera familière. Le HTML est la hiérarchie de la scène : il liste les objets de la page (titre, paragraphe, image) et comment ils sont imbriqués. Le CSS règle les matériaux et la mise en page : couleurs, polices, tailles, positions. Le JavaScript est la couche de script. Vous pourrez l'ajouter plus tard, mais ce n'est pas nécessaire.

    VS Code

    Votre éditeur. Ouvrez le dossier de votre site avec Fichier > Ouvrir le dossier.

    Live Server

    Une extension de VS Code. Clic droit sur index.html, puis Open with Live Server : le navigateur se rafraîchit à chaque sauvegarde (ctrl + s).

    Un navigateur

    Firefox, Brave, etc. Appuyez sur F12 pour ouvrir les outils de développement. Vous les utiliserez plus tard.

    Le dossier que vous aurez à la fin

    Gardez-le plat. Chaque page est à côté du style.css, et les images vont dans un dossier images.

    mon-portfolio/
├── index.html              À propos (la page d'accueil)
├── modele-projet.html      (copier pour chaque projet)
├── lighthouse-keeper-s-secret.html
├── projet-space-jam.html
├── style.css               (un seule css pour toutes les pages)
├── images/
│   ├── portrait.jpg
│   └── lighthouse-cover.png
└── cv.pdf
    Nomenclature

    Minuscules, pas d'espaces, pas d'accents, des tirets entre les mots : lighthouse-keeper-s-secret.html, jamais Lighthouse Keeper's Secret.HTML. Le navigateur vous pardonnera, GitHub Pages non.

    Niveau 1 - 10 min

    Le squelette de toute page

    Toute page HTML commence par les mêmes quelques lignes. Ne les écrivez jamais de zéro : copiez-les. Mais vous devez savoir à quoi elles servent, car la plupart des « ma page est cassée » commencent ici.

    Balises, attributs, imbrication

    • Une balise est un mot entre chevrons. La plupart vont par paire : <p> ouvre, </p> ferme (remarquez le slash).
    • Tout ce qui est entre les deux est le contenu. L'ensemble forme un élément.
    • Un attribut ajoute une information à une balise ouvrante : <a href="page.html">.
    • Les éléments s'imbriquent comme des dossiers. Fermez toujours les éléments de l'intérieur vers l'extérieur.
    <p class="intro">Hello <strong>World</strong></p>
<!-- ↑ balise + attribut   ↑ élément imbriqué  ↑ balise fermante -->
    Commentaires

    Tout ce qui est entre <!-- et --> est ignoré par le navigateur. Utilisez-le pour des notes personnelles, ou pour désactiver un bloc le temps d'un test (ou /* */).

    Texte, titres et listes

    BaliseCe que c'estÀ utiliser pour
    <h1> à <h6>Titres, du plus au moins importantUn seul h1 par page (son titre), puis des h2 pour les sections
    <p>ParagrapheTout bloc de texte
    <strong> <em>Importance, emphaseGras et italique
    <ul> <ol> <li>Liste à puces, liste numérotée, élément de listeCompétences, outils utilisés, ce que vous avez fait sur un projet
    <br> <hr>Saut de ligne, ligne horizontaleRarement. Ces deux-là n'ont pas de balise fermante.
    Piège des espaces

    Le navigateur réduit n'importe quel nombre d'espaces et de retours à la ligne à un seul espace. Appuyer sur Entrée dans votre fichier ne crée pas un nouveau paragraphe sur la page. Utilisez un nouveau <p>.

    Un titre n'est pas une taille de police

    Ne choisissez pas h3 parce qu'il est plus petit. Choisissez le titre dont le niveau est le bon, et changez son apparence avec le CSS plus tard.

    Niveau 3 - 10 min

    Liens, images et chemins

    Deux éléments relient votre page au reste du monde. Tous deux s'appuient sur un chemin, en partant du fichier dans lequel vous écrivez.

    <!-- un lien vers une autre page de TON site -->
<a href="lighthouse-keeper-s-secret.html">Lighthouse Keeper's Secret</a>

<!-- un lien vers le site externe (adresse complète, commence par https) -->
<a href="https://github.com/3Mcrystal" target="_blank">Ma page github</a>

<!-- une image de votre dossier images, avec une description textuelle -->
<img src="images/portrait.jpg" alt="Portrait de Yaël à son bureau">

<!-- un fichier à ouvrir ou télécharger -->
<a href="cv.pdf">Mon CV (PDF)</a>
    href

    Où mène le lien. Vos propres pages : nom du fichier. Sites autre : l'adresse complète en https://.

    target="_blank"

    Ouvre le lien dans un nouvel onglet. Pratique pour les liens externes

    alt

    Décrit l'image pour les lecteurs d'écran, et s'affiche si l'image ne charge pas. Ne l'oubliez jamais.

    Casse-tête de chemins

    La page dans laquelle vous écrivez est surlignée.

    Vous le croiserez

    ../ veut dire « remontez d'un dossier ». Vous n'en avez besoin que si vous mettez des pages dans des sous-dossiers. Notre structure à plat l'évite volontairement.

    Niveau 4 - 7 min

    Organiser une page en zones

    Jusqu'ici, tout est empilé en vrac. Les vraies pages sont découpées en zones. Ces balises n'affichent rien par elles-mêmes. Elles donnent du sens à une zone, et donnent au CSS quelque chose à attraper plus tard.

    BaliseLa zone
    <header>Le haut de la page : votre nom, un logo, la navigation
    <nav>Le menu : un groupe de liens vers vos pages
    <main>Le contenu propre à cette page. Un seul par page.
    <section>Un bloc thématique dans main (À propos, Compétences, Contact)
    <article>Un élément autonome, par exemple une carte de projet
    <footer>Le bas de la page : copyright, liens sociaux
    <div> <span>Des boîtes neutres, sans signification. div pour un bloc, span pour quelques mots dans un texte.

    Donner un nom : class et id

    Pour styliser un élément autrement que les autres, donnez-lui une class (réutilisable, plusieurs éléments peuvent la partager) ou un id (unique sur la page).

    <article class="project-card">
  <h3>Lighthouse Keeper's Secret</h3>
  <p>Un jeu de puzzle en point & click sous SFML.</p>
</article>

    Ajouter une page de projet

    Démo en classe

    En classe, ce niveau est une courte démo : copier le modèle une fois, le renommer, ajouter le lien. Faites l'exercice complet chez vous.

    Exigence du projet 2 - Une page par projet

    Les projets sont facultatifs. Ce qui compte, c'est qu'en ajouter un prenne cinq minutes. Vous le faites en copiant une page modèle. Pas d'outil, pas de commande.

    Copiez le modèle

    Dans VS Code, clic droit sur modele-projet.html, copier, coller. Renommez la copie : lighthouse-keeper-s-secret.html.

    Remplissez-le

    Changez le title, le titre, la ligne de détails, l'image et le texte. Gardez la structure.

    Ajoutez le lien

    Ajoutez un <a> vers la nouvelle page dans le menu de vos pages. Sans lui, personne ne trouvera la page.

    Montrer votre jeu sans faire de version web

    • itch.io : publiez le build là-bas, puis faites un lien vers lui. C'est l'option « jouable » la plus simple.
    • Une vidéo : mettez-la sur YouTube, cliquez sur Partager > Intégrer, et collez le code <iframe> dans votre page. Vérifiez qu'elle fonctionne une fois votre site en ligne.
    • Des captures : trois bonnes images valent mieux qu'un long texte. Ajoutez toujours alt.
    • Votre rôle : dans un projet d'équipe, dites précisément ce que vous avez fait. C'est la première chose qu'un recruteur cherche.
    Plus tard, si vous voulez

    Copier le modèle à la main suffit pour 3 ou 4 projets. Si vous en avez beaucoup, un petit script peut générer les pages à partir d'une liste. C'est l'une des idées bonus du niveau 11.

    Niveau 6 - 15 min

    CSS : lui donner votre style

    Le CSS est une liste de règles. Chaque règle choisit des éléments et dit comment ils doivent apparaître.

    h1 {                      /* sélecteur : quels éléments ? */
  color: #2b45f5;         /* propriété : valeur; */
  font-size: 2.5rem;
}

    Relier une feuille de style

    Mettez vos règles dans un seul fichier, style.css, et reliez-le depuis le <head> de chaque page. Cette seule ligne fait que toutes vos pages partagent le même style.

    <link rel="stylesheet" href="style.css">
    Rien ne change ?

    Vérifiez le nom du fichier et le chemin dans href, sauvegardez les deux fichiers, puis forcez le rafraîchissement avec Ctrl+Maj+R. C'est la cause neuf fois sur dix.

    Les sélecteurs dont vous avez besoin

    SélecteurChoisit
    pTous les paragraphes
    .project-cardTout ce qui a class="project-card"
    #contactL'unique élément avec id="contact"
    nav aLes liens situés dans un nav
    h1, h2Les deux titres (une virgule veut dire « et »)
    a:hoverUn lien pendant que la souris est dessus

    Quand deux règles se contredisent, le sélecteur le plus précis gagne, et à précision égale, celle qui est plus bas dans le fichier gagne. C'est pour cela que « cascade » est dans le nom.

    Les valeurs que vous utiliserez tout le temps

    • Couleurs : des noms (tomato), des codes hexadécimaux (#2b45f5), ou rgb(43 69 245). Utilisez un sélecteur de couleur : VS Code en affiche un quand vous survolez une couleur.
    • Tailles : px est fixe. rem suit la taille de police de base, un bon choix par défaut pour le texte. % est relatif au parent.
    • Polices : font-family: Georgia, serif; liste des solutions de repli dans l'ordre. Pour une police web gratuite, choisissez-en une sur fonts.google.com et collez le <link> fourni dans votre <head>.

    Niveau 7 - en autonomie

    Tout est une boîte

    Le navigateur traite chaque élément comme un rectangle à quatre couches, de l'intérieur vers l'extérieur : le contenu, le padding (espace à l'intérieur de la bordure), la bordure, et la marge (espace à l'extérieur, qui repousse les voisins). La plupart des « pourquoi y a-t-il un espace ici ? » trouvent leur réponse dans cette image. Bougez les curseurs.

    Niveau 8 - en autonomie
    
    
    Mettre en page avec flexbox
    
  
    
  
    
    
    Par défaut, les éléments de type bloc s'empilent verticalement. Mettez display: flex; sur un parent et ses enfants s'alignent en ligne, avec quelques propriétés pour les espacer. C'est ainsi que sont construits les menus, les rangées de cartes et les pieds de page. Jouez avec les contrôles et lisez le CSS produit.
    
  
    
  
    
    
    Labo flexbox
    
    
    
      
      
      
      
      
    
    
    
    
      
    123
    
      
    
    
    
  
    
  
    
    
      
      
    • justify-content répartit les éléments dans le sens principal (la ligne, par défaut). align-items agit dans le sens perpendiculaire.
      • 
      
    • gap met un espace régulier entre les éléments, donc pas besoin de marges sur chacun.
      • 
      
    • Vous voulez une grille de cartes qui s'adapte seule à la largeur de l'écran ? Une règle suffit : display: grid; grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)); gap: 16px;
      • 
    
    
    
    Les téléphones
    
    
    Beaucoup de visiteurs ouvriront votre portfolio sur un téléphone. Deux choses le permettent : la balise meta viewport du niveau 1, et une media query, une règle qui ne s'applique que si l'écran est étroit. Dans les éditeurs de cette page, les media queries suivent la largeur de la fenêtre de votre navigateur, pas celle de la petite zone d'aperçu.
    
  
    
  
    @media (max-width: 600px) {
  nav { flex-direction: column; }   /* empile le menu sur les petits écrans */
}
    
  
    



  
    

    



    
  
    
    
    Niveau 9 - en autonomie
    
    
    Un style qui vous ressemble
    
  
    
  
    Exigence du projet 3 - Votre propre style
    Simple, c'est très bien. Ce qui compte, c'est que vos pages soient cohérentes entre elles et que le rendu soit un choix de votre part, pas celui par défaut du navigateur.
    
  
    
    
    Voici l'astuce qui rend un changement de style facile : écrivez vos couleurs et vos polices une seule fois, en haut de style.css, sous forme de variables, puis utilisez-les partout. Changez une ligne, tout le site change. Essayez sur un mini-site.

    Niveau 10 - en autonomie
    
    
    Mettre votre site en ligne avec GitHub Pages
    
  
    
  
    Pas enseigné en classe
    Vous suivrez ce niveau seul. C'est une exigence du projet, ne le laissez pas pour la dernière minute : essayez tôt, et demandez de l'aide si une étape ne correspond pas à ce que vous voyez.
    
  
    Exigence du projet 4 - En ligne
    Votre site doit être accessible à une adresse publique. GitHub Pages l'héberge gratuitement, directement depuis un dépôt. Un dépôt (repository) est un dossier de votre projet stocké sur GitHub.
    
  
    GitHub est en anglais
    Les boutons et menus sont affichés en anglais. Les termes importants sont donnés ci-dessous en italique avec leur sens.
    
  
    
    
    Créez votre dépôt depuis le modèle
    Ouvrez le dépôt modèle que votre enseignant vous donne. Cliquez sur le bouton vert Use this template (utiliser ce modèle), puis Create a new repository (créer un dépôt).
    
    
    Nommez-le
    Appelez-le votrepseudo.github.io pour obtenir l'adresse courte https://votrepseudo.github.io. Un autre nom fonctionne aussi, l'adresse se termine alors par /nom/. Laissez-le Public.
    
    
    Ajoutez votre contenu
    Cliquez sur un fichier puis sur le crayon pour le modifier en ligne. Ou Add file > Upload files (ajouter des fichiers) pour déposer images et pages. Terminez par Commit changes, qui enregistre le tout.
    
    
    Activez Pages
    Settings > Pages (paramètres). Sous Source, choisissez Deploy from a branch (déployer depuis une branche), branche main, dossier / (root), puis Save.
    
    
    Attendez, puis visitez
    Après une ou deux minutes, l'adresse apparaît en haut de l'écran Pages. L'onglet Actions montre la construction en cours.
    
    
    Mettez à jour quand vous voulez
    Chaque commit sur main republie le site tout seul. Aucune étape en plus.
    
  
    
  
    C'est public
    N'importe qui peut lire votre site et votre CV.
    
  
    
    
    Si vous préférez travailler sur votre ordinateur
    
    
    Modifiez dans VS Code, puis envoyez les changements avec GitHub Desktop (un bouton nommé Push origin), ou avec trois commandes dans le terminal :
    
  
    

    git add .
git commit -m "Ajout de la page Lighthouse Keeper's Secret"
git push

    Ce que vous voyezCause probable
    
    
      
    Une page « 404 » à votre adresseLa page d'accueil doit s'appeler exactement index.html et se trouver à la racine du dépôt. Ou Pages n'est pas encore activé.
    
      
    Ça marche sur votre PC, l'image manque en ligneEn ligne, les noms respectent la casse : Portrait.JPG n'est pas portrait.jpg. Vérifiez aussi les espaces et les accents dans le nom.
    
      
    La page s'affiche, mais sans styleLe href de la balise link ne correspond pas au vrai nom du fichier, ou style.css n'a pas été envoyé.
    
      
    Les liens marchent en local, plus en ligneUn chemin qui commence par / ou C:\. Utilisez des chemins relatifs comme images/cover.png.
    
      
    Vous avez changé quelque chose, le site est identiqueAttendez une minute, puis forcez le rafraîchissement avec Ctrl+Maj+R. Regardez l'onglet Actions : une croix rouge signale une erreur.
    
        
  
    
  
    

    



    
  
    
    
    Niveau 11 - facultatif
    
    
    Bonus : aller plus loin
    
  
    
  
    Rien de tout cela n'est obligatoire. Choisissez ce qui vous tente, et demandez de l'aide si besoin.
    
  
    
    
    Mode sombre, sans JavaScript
    Utilisez les variables du niveau 9 et redéfinissez-les quand le système du visiteur est en mode sombre. Facile.
    
    
    Adapter aux téléphones
    Les media queries et la grille flexible du niveau 8. Testez avec le mode appareil du navigateur (F12 -> icône de téléphone). Facile.
    
    
    Une favicon
    La petite icône de l'onglet. Ajoutez <link rel="icon" href="images/favicon.png"> dans chaque head. Facile.
    
    
    Des aperçus de lien soignés
    Ajoutez les balises meta og:title, og:description et og:image pour que votre lien soit joli quand il est partagé sur Discord ou LinkedIn. Facile.

    transition et transform en CSS. Une carte qui se soulève au survol, ce sont deux lignes. Moyen.
    
    
    Interactions en JavaScript
    Un bouton de thème, un filtre de projets, un carousel d'image de projet. Moyen.
    
    
    Générer les pages de projet automatiquement
    Gardez vos projets dans une liste et laissez un court script construire les cartes ou les pages. Difficile, mais très satisfaisant.
    
    
    Votre propre nom de domaine
    GitHub Pages accepte les domaines personnalisés. Cela coûte quelques euros par an. Moyen.

    :root {
  --bg: #ffffff;

  }

body { background: var(--bg); color: var(--text); }

    Niveau 12 - à garder ouvert
    
    
    Kit de survie
    
  
    
  
    
    
    Votre meilleur outil de débogage : F12
    
    
      
      
    • Onglet Éléments : cliquez sur l'icône flèche, puis sur n'importe quoi dans votre page. Vous voyez son HTML, et chaque règle CSS qui s'applique, avec les règles barrées qui ont perdu. Vous pouvez modifier les valeurs en direct. Rien n'est sauvegardé : recopiez ce qui marche dans votre fichier.
      • 
      
    • Onglet Console : les messages rouges signalent des problèmes.
      • 
      
    • Onglet Réseau : rafraîchissez la page. Une ligne rouge avec 404 est un fichier que le navigateur n'a pas trouvé : mauvais chemin ou mauvais nom.
